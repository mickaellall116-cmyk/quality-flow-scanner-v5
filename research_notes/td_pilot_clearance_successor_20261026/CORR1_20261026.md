## The corr1 fix (minimal diff on the Option B successor)

In `pilot_runner_corr1.py` (see `pilot_runner_corr1.diff`; Option B
stale-marking and repeat-clear idempotence unchanged):

1. **Tripwire-pending gate** (`tripwire_pending`): the current
   session's gate is satisfied only when its tripwire action is
   done AND the latest recorded check for the current session is
   clean.
2. **Held phase in `run_due`** (requirements 1–2): while an
   inherited tripwire hold is active and the gate is unsatisfied,
   the ONLY action that may execute is the due current-session
   tripwire check — no TD-kind action, no archive push. A clean
   check does NOT lift the inherited hold; a dirty check (new reply
   joins `pending_review`) or a failed search keeps the pilot
   fail-closed.
3. **Clearance gate in `process_tripwire_clear`** (requirement 3):
   verdicts are filed as before, but the hold lifts (and prior
   sessions are stale-marked) only once the current session's
   tripwire is recorded clean. If it is not, the clearance file is
   **retained, not consumed**, and a later tick completes the lift;
   the Option B idempotence guard makes re-processing the retained
   file a strict no-op for already-filed ids. A contradiction
   verdict still fires the permanent stop.
